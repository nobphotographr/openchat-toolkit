# OpenChat Toolkit

**Windows向け試用版 · 履歴保存・検索・予約投稿 · AIで自分用にカスタマイズ**

Windows版LINEのオープンチャットを、手元のPCで扱うためのカスタマイズ用ソースコードです。履歴の保存・検索と、投稿の下書き・予約を同じ画面で管理できます。

完成済みの汎用製品ではありません。利用者のPCとLINEの画面で動作確認しながら、CodexやClaude Codeなどで調整して使うことを想定しています。LINE公式の製品ではなく、Windowsアプリの画面操作に依存します。

**最初の一歩：** 下の手順でソースを取得し、[Codex用](prompts/CODEX.md) または [Claude Code用](prompts/CLAUDE-CODE.md) の依頼文を渡してください。初期状態では自動取得も投稿も動きません。

## できること

| 機能 | 内容 |
|---|---|
| 投稿 | 下書き、本文プレビュー、単発予約、直近の時刻で予約、取消、一時停止 |
| 繰り返し | 毎日・曜日指定・期間指定、停止・再開 |
| テンプレート | 本文・画像の保存、分類、複製 |
| 画像添付 | PNG/JPEGを1枚添付。本文と画像は別々のメッセージとして送信 |
| 履歴 | PCの履歴ダウンロード、スマホから書き出した履歴の取込 |
| 画面取得 | ダウンロードに失敗する部屋で画面から本文を取得。途中保存・再開 |
| 検索 | キーワード、日付・ルーム別、ブックマーク、共有リンク |
| 定期取得 | 1日1回。PC復帰後の補完と、取得途中の分割再開 |

初期設定には宛先・投稿・履歴・認証情報を含めません。定期取得は無効、予約投稿は一時停止から始まります。Slack・GAS・個人用集計システムの接続は含みません。

## 最初に使う

このページの **Code → Download ZIP** からダウンロードし、ZIPを展開してください。Gitを使う場合は次のコマンドで取得できます。

```powershell
git clone https://github.com/nobphotographr/openchat-toolkit.git
cd openchat-toolkit
```

自分の変更をGitHubにも保存したい場合は、先にForkを作ってそのコピーで作業してください。設定・履歴・予約データはForkにもコミットしないでください。

前提：Windows 10/11、Python 3.11以降、Windows版LINE、日本語表示。ネイティブ操作の元実装は画面倍率150%で検証されています。別の表示倍率・LINEのバージョンでは調整が必要な場合があります。ビルドにはWindowsの.NET Framework 4.xのC#コンパイラを使います。

1. このフォルダーを、書き込み可能な場所に置きます。普段使っている別のLINE自動操作アプリとは分けてください。
2. `初期設定.cmd` を実行します。専用Python環境、C#ヘルパー、空の設定を作成します。ネットワークからのパッケージ取得やタスク登録は行いません。
3. `Start.cmd` を実行します。Edgeのアプリ形式の画面を開きます。Edgeが見つからない場合は通常のブラウザを使います。
4. 「アプリ設定」で、LINEに表示されるルーム名の**全文**を登録して保存します。投稿専用の部屋は定期取得をオフにして登録できます。
5. 投稿は「投稿を作成」で下書きを保存します。宛先・本文・画像・予定時刻を確認して予約します。初期状態ではまだ送信されません。

PowerShellでPythonを指定する場合：

```powershell
.\setup.ps1 -PythonPath 'Pythonの実行ファイルのフルパス'
```

保護設定やWindowsのロック設定は自動変更しません。警告が出た場合は対象ファイルを確認してください。

## 定期実行を有効にする

初回は自分で用意したテストルームで、送信先と本文を確認して試してください。他人がいる通常のルームをテストに使わないでください。

```powershell
# 履歴取得の判定タスク
.\register_task.ps1 -Kind collection
# 予約投稿の判定タスク
.\register_task.ps1 -Kind posting
```

その後、履歴取得は「アプリ設定」で有効にします。予約投稿は「予約・実行履歴」で再開します。**再開すると、時刻に達した有効な予約が送信対象になります。**

タスクは毎分、実行対象の有無を確認します。毎分履歴をダウンロードするわけではありません。通常の履歴巡回は1日1回、既定では日本時間03:00以降です。PCの復帰後は当日未取得の部屋を補完します。画面取得の続きは5分以上の間隔で、1部屋につき1日最大12回の枠内で進めます。電源オフの日数分を一斉に再実行する設計ではありません。

タスクはログイン中のユーザーとして、管理者権限を使わず実行します。LINEへのログイン、ロック解除された操作可能なデスクトップが必要です。スリープ・ロック・RDP切断中の操作は保証できません。LINEを操作する別のソフトとは同時実行しないでください。

状態確認・解除は、このフォルダーのタスクだけが対象です。

```powershell
.\register_task.ps1 -Kind posting -StatusOnly
.\register_task.ps1 -Kind collection -StatusOnly
.\register_task.ps1 -Kind posting -Remove
.\register_task.ps1 -Kind collection -Remove
```

## 投稿のルール

- 送信時間は日本時間08:00以上21:00未満です。08:00前の指定は当日08:00、21:00以降は翌日08:00へ調整し、確認画面に表示します。
- 「直近の時刻で予約」は約2分後を指定します。確定操作とワーカーの起動が必要で、クリック直後の送信ではありません。
- 単発予約は予定から24時間を超えると期限切れになります。繰り返し予約は過去の日の分をまとめて送信しません。
- 本文は4,000 UTF-16コード単位以内。PNG/JPEGは1枚、10MB以内です。動画投稿は対象外です。
- 宛先の全文、ウィンドウ、入力欄、本文の一致を確認します。送信操作の前にDBへ記録します。
- 送信結果が分からない場合や処理が途中で終了した場合は「要確認」で止め、自動再送しません。「確認終了」は再送せず記録を閉じる操作です。
- 「LINE画面に表示済み」は送信側の画面での確認です。サーバーへの到達や相手の既読を保証する表示ではありません。

## 履歴を残す仕組み

履歴ファイルを毎回取得しても、保存済みの過去の会話を削除する処理はありません。元ファイルと追加したレコードをSQLiteに保持し、同じ内容の再取込を抑制します。

LINE側の保存期限で既に消えた履歴は復元できません。画面取得で過去の保存位置とのつながりを確認できない場合は、欠落がないことにして進めず、要確認にします。本文内の日付などが曖昧なテキスト形式では完全なメッセージ同定はできないため、元の履歴も保持します。スマホ取込とPC取込の重複は、書式の違いから完全には統合しません。

画像の**投稿**はできますが、会話内の画像・動画の自動保存はこの版に含みません。

## データと公開範囲

`collector-config.json` と `state/` に、設定、履歴、本文、画像、予約、ブラウザセッションを保存します。これらをGitへ追加しないでください。アプリのサーバーは `127.0.0.1` だけで待ち受けます。履歴検索に外部AI/APIは不要です。

`state/` は暗号化保管ではありません。PCの利用者権限で保護し、共有PCには注意してください。バックアップはタスクと画面を終了してからフォルダーを複製するか、SQLiteのバックアップAPIを使ってください。使用中のDBファイルだけをコピーしないでください。

公開対象は `release-files.json` の一覧に限定します。`.gitignore` だけを頼りに使用中のフォルダー全体をアップロードしないでください。

## 開発とテスト

```powershell
python audit_release.py
python run_tests.py
```

テストは一時フォルダーにソースと合成データを用意して実行します。C#ビルド、DB・予約・認証付きローカルHTTP・画像変換を確認し、LINEの操作・送信・タスク登録は行いません。Node.jsがあればフロントエンドの回帰テストも実行します。無い場合は未実行と表示します。CIはWindows/Python 3.11/Node.jsで同じテストを行う構成です。

この切り出し版の実LINE送信と、他のPCでの動作確認は初回共有時点では未実施です。元の個人用アプリの動作実績と、この版の実機検証を同一扱いにしないでください。
